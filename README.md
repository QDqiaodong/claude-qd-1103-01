# 奶茶饮品店 · 原料库存与配方出单

奶茶饮品店的原料库存、配方出单、会员积分与出杯退款管理，并提供**会员档案合并与联系方式变更审计**。后端 Spring Boot + JPA，前端 Vue 3 + Element Plus（焦糖主题、顶部标签页导航）。

## 启停

```bash
sh start.sh     # 启动（后端 + 前端 + MySQL）
sh stop.sh      # 停止
```

## 模块

- 原料库存：茶底 / 奶 / 小料 / 糖浆 的库存与启用停用
- 配方出单：勾选小料 + 右侧抽屉填份数生成配方（小料用量用 `@ElementCollection Map` 承载）；每杯另固定消耗茶底 10（`Dict.BASE_TEA_PER_CUP`）
- 会员：有效会员手机号唯一，消费累加积分并按阈值升级（银卡 ≥ 500，金卡 ≥ 2000）；手机号/姓名变更必须留痕
- 会员合并：待处理 / 冲突待处理 / 已合并 / 已撤销 四态工单，历史订单与积分流水统一归主档、可由负责人撤销
- 出杯记录：按配方明细汇总金额，仅「已出杯」可退款并回退积分

## 出杯库存履约闭环

- **下单前预览**：出杯页按每个配方的茶底 + 小料汇总本单原料需求（多个配方、重复明细合并计算），页面展示预计扣减与不足/停用原料；预览仅为提示，提交时服务端在事务内对原料行加悲观写锁、以最新库存复核。
- **整单原子**：任一原料库存不足、已停用或配方引用失效，整单不落库（`cup_order` / 明细 / 库存 / 积分同事务回滚，无负库存、无半扣、积分不先行增加），仅在「出杯失败记录」表留存失败原因；同一原料被两笔出杯并发争用时由行锁串行化，不可能两单都成功。
- **扣减快照**：出杯成功时逐原料保存 `cup_order_stock_snapshot`（原料 id、当时名称/单位、实际用量），之后配方被编辑也不改变历史消耗。
- **退款回补**：仅「已出杯」订单可退款且只退一次；严格按该订单快照精确回补原料（登记 `refund_qty`）并回退原积分，重复点击/并发退款由订单行锁与状态判定稳定拒绝。历史无快照的旧订单仍可退款，但只回退积分、不凭空回补库存。

## 会员档案合并与联系方式变更审计

### 合并流程（会员合并页）

1. **标记待合并**：店员选择保留的**主档**与待并入的**重复档**、填写合并原因；系统立即检查冲突：
   - `PHONE_CONFLICT`：两边手机号相同（线下遗留同号重复绑定），或号码还被第三张有效档案占用；
   - `POINTS_SOURCE`：会员当前积分余额与其积分流水合计不一致。
   有任一冲突工单进入「**冲突待处理**」，绝不静默覆盖任何一边的手机号或积分。
2. **预览**：工单详情对照展示两边手机号、姓名、积分、流水合计、历史订单数，并实时给出预检冲突。
3. **解决冲突（仅负责人）**：必须明确选择主档保留哪边的手机号；积分来源必须二选一——
   `TRUST_BALANCE`（以当前余额为准，补一条调平流水）/ `REBUILD_FROM_LEDGER`（以流水合计重建余额，差异留痕）。
4. **执行合并**：历史订单 `cup_order.member_id`、积分流水 `member_points_ledger.member_id`、
   联系方式审计 `current_member_id` 统一迁到主档（**只迁不复制**）；主档积分=两边积分之和；
   原档置 `已合并` 只读别名（保留原手机号/姓名快照、主档指针 `merged_into_id`、合并原因、操作人、时间），
   工单保存合并前 JSON 快照与结果摘要。
5. **撤销合并（仅负责人）**：按 `origin_member_id` 把订单与流水**还原**回原档（合并期间主档新赚的积分不动），
   两边余额各自按流水合计重建，积分全程只计算一次；原手机号被占用时拒绝撤销、要求先处理。

### 联系方式变更审计

- 改手机号/姓名必须走 `/members/{id}/contact-change` 并填写原因；
  `member_contact_change_log` 保留字段、变更前后值、原因、操作人、生效时间，合并后仍可在主档视图追溯。
- 同一手机号不能绑定两个有效会员：`member_phone_guard` 守卫行按号码升序 `SELECT … FOR UPDATE`
  + 主键唯一约束 + 会员行 `@Version` 乐观版本三重保证。
- 旧的静默 `PUT /members/{id}` 改手机/姓名/积分入口已禁用，积分调整一律写流水。

### 并发与幂等（服务端按最新版本校验）

- 工单行、会员行（按 id 升序）、手机号守卫行（按号码升序）全部悲观写锁，会员/工单带 `@Version`；
- 重复标记、重复合并（幂等返回已合并工单）、并发合并、并发改手机号、重复撤销都得到稳定结果，
  锁等待返回 409、版本过期返回 409，业务规则不满足返回 400。

### 验收

`acceptance_member_merge.py`（真实 HTTP + 真实 MySQL 行锁，74 项断言）覆盖：

负责人撤销与积分不重复、重复标记/合并/撤销幂等、并发合并与并发改手机号、合并后退款再撤销的完整链路。
